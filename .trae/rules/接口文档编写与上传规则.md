# 接口文档编写与上传规则

## 一、核心原则

**所有后端接口开发必须遵循"代码完成 → 文档编写 → 审查通过 → 上传Apifox"的标准化流程**，确保接口文档与代码实现完全同步，避免文档滞后或缺失。

---

## 二、适用范围

### 2.1 适用场景

| 场景 | 说明 | 是否需要文档 |
|------|------|-------------|
| **新增接口** | 创建新的API接口 | ✅ **必须** |
| **修改接口** | 修改现有接口的参数、响应或逻辑 | ✅ **必须** |
| **删除接口** | 删除不再使用的接口 | ✅ **必须**（标记废弃） |
| **接口优化** | 性能优化、代码重构（不影响接口定义） | ❌ **不需要** |
| **内部接口** | 仅内部使用的测试接口 | ⚠️ **可选** |



## 三、接口文档编写规范

### 3.1 文档格式

**必须使用OpenAPI 3.0规范**（YAML或JSON格式），确保：
- ✅ 符合行业标准
- ✅ 可直接导入Apifox
- ✅ 支持自动化工具
- ✅ 便于团队协作

---

### 3.2 文档内容要求

#### 必须包含的信息：

**基础信息**：
```yaml
- 接口名称（中文 + 英文）
- 接口描述（详细说明功能）
- 请求方法（GET/POST/PUT/DELETE）
- 接口路径（遵循RESTful规范）
- 认证要求（是否需要Token）
```

**请求参数**：
```yaml
- 参数名称
- 参数类型（query/path/body/header）
- 数据类型（string/integer/boolean/object/array）
- 是否必填
- 参数说明
- 示例值
- 校验规则（长度、范围、格式）
```

**响应结构**：
```yaml
- 响应码（200/400/401/403/404/500）
- 响应数据结构
  - 字段名称
  - 数据类型
  - 字段说明
  - 示例值
- 错误响应结构
  - 错误码
  - 错误信息
  - 错误详情
```

**数据模型**：
```yaml
- 数据模型定义（DTO、Entity等）
- 模型字段说明
- 模型引用关系
```

---

### 3.3 文档命名规范

**文件命名格式**：
```
{模块名}-{版本号}-api.yaml
例如：
- simulation-jobs-v1.0-api.yaml
- auth-v1.0-api.yaml
- molecules-v1.0-api.yaml
```

**存放位置**：
```
docs/api/
├── modules/              # 模块接口文档
│   ├── simulation-jobs-v1.0-api.yaml
│   ├── auth-v1.0-api.yaml
│   └── molecules-v1.0-api.yaml
├── openapi-complete-spec.yaml  # 完整接口规范
└── archive/              # 归档文档
    └── simulation-jobs-v0.9-api.yaml
```


### 5.1 审查检查清单

**技术负责人必须检查以下内容**：

#### 代码审查：
- ✅ 代码逻辑正确性
- ✅ 参数校验完整性
- ✅ 异常处理完善性
- ✅ 安全性检查（SQL注入、XSS等）
- ✅ 性能优化（查询效率、缓存等）
- ✅ 代码规范（命名、注释、格式）

#### 文档审查：
- ✅ 接口路径符合RESTful规范
- ✅ 参数定义完整准确
- ✅ 响应结构清晰明确
- ✅ 错误处理说明完整
- ✅ 示例数据真实合理
- ✅ 认证要求标注正确
- ✅ 数据模型定义准确

#### 一致性审查：
- ✅ 文档与代码实现完全一致
- ✅ 参数名称与代码变量名一致
- ✅ 响应结构与实际返回一致
- ✅ 错误码与实际错误一致



## 六、上传到Apifox流程

### 6.1 自动上传（推荐）

**使用Apifox CLI自动上传**：

```bash
# 步骤1：登录Apifox
apifox login --with-token {您的访问令牌}

# 步骤2：上传接口文档
apifox import --project {项目ID} --format openapi --file {文档路径}

# 步骤3：验证上传结果
apifox endpoint list --project {项目ID}
```

**优势**：
- ✅ 快速高效（10秒完成）
- ✅ 自动化流程
- ✅ 支持批量上传
- ✅ 可集成CI/CD

---

### 6.2 手动上传（备用）

**通过Apifox客户端手动上传**：

**步骤**：
1. 打开Apifox客户端
2. 登录账号
3. 打开目标项目
4. 点击"导入" → "OpenAPI/Swagger"
5. 选择文件：`docs/api/modules/{模块名}-api.yaml`
6. 设置导入选项：
   - 接口覆盖模式：智能合并
   - 导入到分组：指定分组
7. 点击"确认导入"
8. 验证导入结果

---

### 6.3 上传后验证

**必须验证以下内容**：
- ✅ 接口数量正确
- ✅ 接口路径正确
- ✅ 参数定义正确
- ✅ 响应结构正确
- ✅ 认证配置正确
- ✅ 分组归类正确

## 八、版本管理

### 8.1 文档版本控制

**版本号格式**：`v{主版本}.{次版本}.{修订号}`

**版本规则**：
- **主版本**：重大变更（接口重构、大规模修改）
- **次版本**：功能新增（新增接口、新增参数）
- **修订号**：小幅修改（参数说明、示例数据）


## 九、异常处理

### 9.1 文档与代码不一致

**发现不一致时的处理流程**：
```
步骤1：立即暂停接口使用
  ↓
步骤2：通知技术负责人
  ↓
步骤3：确认正确版本（代码或文档）
  ↓
步骤4：修正错误的一方
  ↓
步骤5：重新审查
  ↓
步骤6：更新Apifox

### 9.3 上传失败处理

**Apifox上传失败时**：
- ✅ 检查文档格式（OpenAPI规范）
- ✅ 检查网络连接
- ✅ 检查令牌有效性
- ✅ 使用手动上传备用方案
- ✅ 通知Apifox技术支持

## 十六、附录

### 16.1 OpenAPI文档模板

**标准模板**：
```yaml
openapi: 3.0.3
info:
  title: {模块名称} API
  description: {模块描述}
  version: 1.0.0

paths:
  /{接口路径}:
    {请求方法}:
      summary: {接口名称}
      description: {接口描述}
      operationId: {操作ID}
      security:
        - BearerAuth: []
      parameters:
        - name: {参数名}
          in: {参数类型}
          required: {是否必填}
          schema:
            type: {数据类型}
          description: {参数说明}
          example: {示例值}
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/{模型名}'
      responses:
        '200':
          description: {成功描述}
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/{响应模型}'
        '400':
          description: {错误描述}
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/Error'

components:
  schemas:
    {模型名}:
      type: object
      properties:
        {字段名}:
          type: {数据类型}
          description: {字段说明}
          example: {示例值}
```
