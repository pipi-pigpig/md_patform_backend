# 文件输入输出规则

## 一、设计原则

所有计算引擎、后处理等产生的输入输出文件，必须严格遵循以下原则：

| 原则 | 说明 |
|------|------|
| **用户隔离** | 不同用户的文件存储在独立目录，禁止跨用户访问 |
| **任务隔离** | 每个任务拥有独立的工作目录，文件互不干扰 |
| **结构清晰** | 按功能模块划分目录，便于文件管理与检索 |
| **数据库绑定** | 文件路径与数据库记录一一对应，支持快速定位 |
| **路径唯一** | 所有文件路径通过`用户ID+任务ID+文件类型`唯一确定 |
| **零硬编码** | 代码中绝对禁止出现硬编码路径，全部通过`PathUtil`工具类生成 |

## 二、根目录配置

根目录通过`application.yml`配置：

```yaml
md-platform:
  file-storage:
    root-path: data/md_platform_data/
```

## 五、文件命名规范

| 文件类型 | 命名规则 | 示例 |
|---------|---------|------|
| 分子模板文件 | {molecule_name}.lt | EC.lt, LiPF6.lt |
| 分子结构文件 | {molecule_name}.pdb | EC.pdb, Li.pdb |
| LAMMPS输入脚本 | in.{stage} | in.minimization, in.production |
| LAMMPS结构文件 | {stage}.data | minimized.data, equilibrated.data |
| 轨迹文件 | dump.{type}.lammpstrj | dump.trajectory.lammpstrj |
| 计算结果文件 | {property}_result.json | conductivity_result.json |
| 图表数据文件 | {type}_curve.json | rdf_curve.json |
| 临时文件 | job_{jobId}_{name}.tmp | job_123_packmol.tmp |

**命名要求：**
- 全部小写，单词用下划线分隔
- 禁止中文、空格、特殊字符
- 必须包含明确类型标识

## 六、PathUtil工具类使用规范

### 6.1 必须使用PathUtil生成路径

```java
// 正确用法 - 使用PathUtil
Path inputPath = pathUtil.getInputPath(userId, jobId);
Path outputPath = pathUtil.getOutputPath(userId, jobId);

// 错误用法 - 禁止硬编码
Path inputPath = Path.of("data/user_1/jobs/job_1/inputs");  // 禁止！
```

### 6.2 PathUtil核心方法

| 方法 | 返回路径 | 说明 |
|------|---------|------|
| `getJobRootPath(userId, jobId)` | user_{userId}/jobs/job_{jobId}/ | 任务根目录 |
| `getInputPath(userId, jobId)` | user_{userId}/jobs/job_{jobId}/inputs/ | 输入文件目录 |
| `getOutputPath(userId, jobId)` | user_{userId}/jobs/job_{jobId}/raw_outputs/ | 原始输出目录 |
| `getPostProcessingPath(userId, jobId)` | user_{userId}/jobs/job_{jobId}/post_processing/ | 后处理目录 |
| `getVisualizationPath(userId, jobId)` | user_{userId}/jobs/job_{jobId}/visualization/ | 可视化目录 |
| `getReportPath(userId, jobId)` | user_{userId}/jobs/job_{jobId}/report/ | 报告目录 |
| `getGlobalTempPath(type)` | temp/{type}_temp/ | 全局临时目录 |
| `getMoleculeTemplatePath(name)` | system_templates/molecule_templates/{name}/ | 分子模板目录 |
| `getRelativePath(userId, jobId, absolutePath)` | 相对路径字符串 | 获取相对路径 |

### 6.3 数据库存储规范

数据库中**只存储相对路径**（相对于任务根目录），绝对路径运行时动态生成：

```java
// 存入数据库 - 相对路径
String relativePath = pathUtil.getRelativePath(userId, jobId, pdbPath);
simulationInput.setPdbFilePath(relativePath);

// 从数据库读取 - 动态生成绝对路径
String relativePath = simulationInput.getPdbFilePath();
Path absolutePath = pathUtil.resolveAbsolutePath(userId, jobId, relativePath);
```

## 七、文件生命周期管理

| 文件类型 | 生命周期 | 清理策略 |
|---------|---------|---------|
| 输入文件 (inputs/) | 永久保留 | 任务完成后不删除 |
| 原始输出 (raw_outputs/) | 永久保留 | 任务完成后不删除 |
| 后处理结果 (post_processing/) | 永久保留 | 任务完成后不删除 |
| 可视化文件 (visualization/) | 永久保留 | 任务完成后不删除 |
| 报告文件 (report/) | 永久保留 | 任务完成后不删除 |
| 临时文件 (temp/) | 24小时 | 每天凌晨自动清理 |

## 八、原子写入规范

所有文件写入必须采用"临时文件→重命名"原子操作：

```java
// 原子写入示例
public void writeAtomic(Path targetPath, String content) throws IOException {
    Path tempPath = targetPath.resolveSibling(targetPath.getFileName() + ".tmp");
    
    // 1. 写入临时文件
    Files.writeString(tempPath, content);
    
    // 2. 原子替换
    Files.move(tempPath, targetPath, StandardCopyOption.REPLACE_EXISTING, 
               StandardCopyOption.ATOMIC_MOVE);
}
```

## 十、开发强制要求

1. **所有文件操作前必须校验路径存在性和权限**
2. **所有写入操作必须使用原子写入方法**
3. **所有文件操作必须捕获`IOException`并记录详细日志**
4. **临时文件必须在`finally`块中删除**
5. **单元测试必须覆盖所有路径生成逻辑**
6. **禁止在代码中出现任何硬编码路径字符串**
