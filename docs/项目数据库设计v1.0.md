# 项目数据库设计 v1.0

## 1. 数据库概述

### 1.1 数据库基本信息
- **数据库名称**: md_database
- **数据库类型**: MySQL (TiDB Cloud)
- **字符集**: utf8mb4
- **排序规则**: utf8mb4_unicode_ci
- **存储引擎**: InnoDB
- **连接地址**: gateway01.ap-southeast-1.prod.aws.tidbcloud.com:4000

### 1.2 数据库配置
```yaml
连接池配置:
  最大连接数: 20
  最小空闲连接数: 5
  连接超时时间: 30000ms
  空闲超时时间: 600000ms
  最大生命周期: 1800000ms

JPA配置:
  DDL模式: none
  显示SQL: false
  方言: MySQL8Dialect
  批处理大小: 20
```

### 1.3 数据表统计
本项目共包含 **10** 个数据表，分为以下几类：

| 类别 | 表名 | 说明 |
|------|------|------|
| 用户管理 | sys_user_table | 系统用户表 |
| 用户管理 | sys_role_table | 系统角色表 |
| 用户管理 | sys_operation_log_table | 系统操作日志表 |
| 电解液系统 | electrolyte_systems_table | 电解液系统配置表 |
| 模拟计算 | simulation_jobs_table | 模拟任务表 |
| 模拟计算 | simulation_input_table | 模拟输入参数表 |
| 模拟计算 | simulation_raw_output_table | 模拟原始输出表 |
| 模拟计算 | calculation_result_table | 计算结果表 |
| 模拟计算 | job_execution_log_table | 任务执行日志表 |
| 分子模板 | molecule_template_table | 分子模板表 |

## 3. 表关系设计

### 3.1 关系图

```
sys_user_table (用户)
    ├── 1:N → electrolyte_systems_table (电解液系统)
    ├── 1:N → simulation_jobs_table (模拟任务)
    ├── 1:N → sys_operation_log_table (操作日志)
    ├── 1:N → molecule_template_table (分子模板)
    └── N:1 → sys_role_table (角色)

electrolyte_systems_table (电解液系统)
    └── 1:N → simulation_jobs_table (模拟任务)

simulation_jobs_table (模拟任务)
    ├── 1:1 → simulation_input_table (模拟输入)
    ├── 1:1 → simulation_raw_output_table (模拟输出)
    ├── 1:N → calculation_result_table (计算结果)
    └── 1:N → job_execution_log_table (执行日志)
```

### 3.2 外键关系说明

| 主表 | 从表 | 关系类型 | 外键字段 | 说明 |
|------|------|----------|----------|------|
| sys_user_table | electrolyte_systems_table | 1:N | user_id | 一个用户可创建多个电解液系统 |
| sys_user_table | simulation_jobs_table | 1:N | user_id | 一个用户可创建多个模拟任务 |
| sys_user_table | sys_operation_log_table | 1:N | user_id | 一个用户可有多条操作日志 |
| sys_user_table | molecule_template_table | 1:N | create_user_id | 一个用户可创建多个分子模板 |
| sys_role_table | sys_user_table | 1:N | role_id | 一个角色可分配给多个用户 |
| electrolyte_systems_table | simulation_jobs_table | 1:N | system_id | 一个电解液系统可运行多个模拟任务 |
| simulation_jobs_table | simulation_input_table | 1:1 | job_id | 一个任务对应一个输入配置 |
| simulation_jobs_table | simulation_raw_output_table | 1:1 | job_id | 一个任务对应一个输出结果 |
| simulation_jobs_table | calculation_result_table | 1:N | job_id | 一个任务可产生多个计算结果 |
| simulation_jobs_table | job_execution_log_table | 1:N | job_id | 一个任务可有多条执行日志 |

## 4. 索引设计策略

### 4.1 主键索引
所有表均使用自增BIGINT类型作为主键，确保高效的主键查询性能。

### 4.2 唯一索引
对需要保证唯一性的字段建立唯一索引：
- username, email (用户表)
- role_name, role_code (角色表)
- molecule_name (分子模板表)
- job_id (模拟输入表、模拟输出表)

### 4.3 外键索引
外键字段自动创建索引，优化关联查询性能。

### 4.4 业务索引
根据查询场景，建议在以下字段添加索引：
- simulation_jobs_table.status (按状态查询任务)
- simulation_jobs_table.create_time (按时间查询任务)
- calculation_result_table.property_name (按属性名称查询结果)

## 5. 数据完整性约束

### 5.1 非空约束
关键字段设置为NOT NULL，确保数据完整性：
- 用户名、密码
- 系统名称、溶剂信息
- 任务名称、软件名称、状态
- 属性名称、属性值、单位

### 5.2 默认值约束
为常用字段设置合理的默认值：
- status: 'PENDING' (任务状态)
- hardware_used: 'CPU' (硬件类型)
- cpu_cores: '8' (CPU核心数)
- time_step_fs: 1.0 (时间步长)
- is_public_template: false (是否公开)

### 5.3 JSON字段约束
使用JSON类型存储复杂结构数据：
- solvent_info, salt_info, additive_info (电解液系统)
- target_properties, result_summary (模拟任务)
- minimization_params, equilibrium_params, production_params (模拟输入)
- property_detail (计算结果)
- force_field_params (分子模板)

---

## 6. 数据安全设计

### 6.1 密码存储
用户密码使用BCrypt算法加密存储，确保安全性。

### 6.2 敏感信息
- 数据库连接信息通过配置文件管理
- 不在代码中硬编码敏感信息
- 使用SSL/TLS加密数据库连接

### 6.3 数据备份
建议定期备份以下关键数据：
- 用户数据和角色配置
- 电解液系统配置
- 模拟任务和结果数据

---

## 7. 性能优化建议

### 7.1 分区策略
对于数据量较大的表，建议采用分区策略：
- job_execution_log_table: 按时间分区
- calculation_result_table: 按job_id分区

### 7.2 归档策略
对于历史数据，建议定期归档：
- 已完成任务超过6个月的执行日志
- 已删除用户的操作日志

### 7.3 缓存策略
建议对以下数据进行缓存：
- 用户信息和角色权限
- 分子模板信息
- 系统配置信息

-- 查询用户的电解液系统
SELECT s.* 
FROM electrolyte_systems_table s
WHERE s.user_id = ?;

-- 统计任务执行状态
SELECT status, COUNT(*) as count
FROM simulation_jobs_table
GROUP BY status;
